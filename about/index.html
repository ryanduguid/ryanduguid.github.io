What I build

I organise the work into four layers. Data and ledger tools pull figures out of accounting systems without breaking them. Rules and engine tools package deterministic calculations and statutory tests. Agent workflows let an AI coding assistant run those engines inside a fixed boundary, so the calculation stays deterministic even when the assistant is not. Review controls keep incomplete packs and close exceptions in view for a person to assess.

How the work is grounded

  • Primary sources only. Rates, thresholds and tests come from Commonwealth legislation, the regulator's published guidance, or the accounting standard, never from a summary of one.
  • Exact currency arithmetic. Currency calculations in the statutory engines use fixed-point decimals, so binary floating point drift never reaches a figure someone might lodge.
  • Refusal over guessing. Where the law does not settle a treatment, or the records supplied do not establish the fact the law tests, the tools return an unknown instead of a number.
  • Synthetic data in public. Every public fixture, test and example uses fabricated data. Client information stays out of public repositories entirely.
  • A person signs off. The tools calculate and check. Professional judgement and lodgement stay human.

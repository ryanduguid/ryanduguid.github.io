# Manager review gate evaluation

Reproduce the released review-ready gate against 2 fictional BAS packs, then inspect the exact expected result and human boundary.

Published 26 August 2026. Last reviewed 23 September 2026.

## Accounting problem

Before manager review, the preparer needs repeatable checks for completeness and unresolved blocking items against the configured rules.

## Fictional inputs

The evaluation uses the repository fixtures examples/bas-not-ready and examples/bas-ready. They contain no client data.

## Expected result

These results describe readiness for review; a manager still decides whether work may progress.

Pack | Released expectation
Incomplete BAS | Exit 2 with NOT_READY.
Corrected BAS | Exit 0 with READY and no configured findings.

## Controls triggered

- MISSING_ARTEFACT for gst_control_gl
- SELF_REVIEW_INCOMPLETE
- OPEN_ITEM_BLOCKING

## Human decision

READY means no configured gate tripped; it is not approval, advice or lodgement authority.

A manager still judges correctness, risk, materiality, client impact and whether the pack may progress.

## Reproduce

```
git clone --branch review-ready-gate/v0.1.3 --depth 1 https://github.com/ryanduguid/accounting-review-pipeline.git
cd accounting-review-pipeline/packages/review-ready-gate
uv sync --locked --all-extras
uv run review-ready gate --profile bas --pack examples/bas-not-ready --output outputs/evaluation-not-ready
uv run review-ready gate --profile bas --pack examples/bas-ready --output outputs/evaluation-ready
uv run pytest tests/test_evaluation_pack.py -q
```

## Limitations

This evaluates configured gates against fictional inputs. It does not establish that a pack is correct, approve work, provide advice or authorise lodgement. See Evidence and Assurance for the common assurance record and boundaries.

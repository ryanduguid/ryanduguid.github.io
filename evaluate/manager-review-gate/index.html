Manager review gate evaluation

Reproduce the released review-ready gate against two fabricated BAS packs, then inspect the exact expected result and human boundary.

Published 26 August 2026. Last reviewed 26 August 2026.

On this page

Accounting problem Fabricated inputs Expected result Controls triggered Human decision Reproduce Primary sources Versions Limitations

Accounting problem

Before a BAS pack reaches a manager, a preparer needs a repeatable check that the configured completeness and blocking-item gates have not tripped.

Fabricated inputs

The evaluation uses the repository fixtures examples/bas-not-ready and examples/bas-ready. They contain no client data.

Expected result

Pack Released expectation
Incomplete BAS Exit 2 with NOT_READY.
Corrected BAS Exit 0 with READY and no configured findings.

Controls triggered

  • MISSING_ARTEFACT for gst_control_gl
  • SELF_REVIEW_INCOMPLETE
  • OPEN_ITEM_BLOCKING

Human decision

READY means no configured gate tripped; it is not approval, advice or lodgement authority.

A manager still judges correctness, risk, materiality, client impact and whether the pack may progress.

Reproduce

git clone --branch v0.1.1 --depth 1 https://github.com/ryanduguid/workpaper-review-gate.git
cd workpaper-review-gate
uv sync --locked --all-extras
uv run review-ready gate --profile bas --pack examples/bas-not-ready --output outputs/evaluation-not-ready
uv run review-ready gate --profile bas --pack examples/bas-ready --output outputs/evaluation-ready
uv run pytest tests/test_evaluation_pack.py -q

Limitations

This evaluates configured gates against fabricated inputs. It does not establish that a pack is correct, approve work, provide advice or authorise lodgement. See Evidence and Assurance for the common assurance record and boundaries.

Data and privacy boundary

All public fixtures and worked examples are fabricated and synthetic. Client sensitive data belongs in a separately controlled local working directory. It must never be placed in a public issue, public repository or enquiry email.

  • The ATO benchmark client-data control records the zero-network runtime boundary.
  • The Payday Super local file boundary, TheWIPTally local file boundary and review-ready-gate data boundary state how client files are separated from public fixtures.
  • The MCP client architecture describes a local stdio process. The Xero scope and credential boundary separately records that product's read-only API and local token controls.
  • The Coal LSL calculator source makes the browser implementation inspectable.

Passing tests proves only the specified behaviour under the tested conditions. It does not prove a real-world accounting conclusion or a client outcome.

Human accountability and refusals

Human review remains mandatory. Posting to a ledger, making a payment, approving work, lodgment, locking a period and resolving professional judgement are human actions. A tool must refuse or escalate missing, contradictory, stale or out-of-scope facts rather than invent a result. Each product page records its specific inputs, refusal conditions, source-currency limits and human decision boundary.

Independent evaluation

No firm review or testimonial is published yet. Named, anonymous or private feedback will only be used with recorded permission. A future evaluation will state its scope and method and will not be presented as regulatory approval or proof of outcomes beyond that evaluation.

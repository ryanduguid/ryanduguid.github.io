# Subcontract ledger workflows for construction and mining

These are Claude Code skills rather than a standalone calculator, so an AI coding agent has to be set up first. They cover progress claims, retention schedules, work in progress and overbilling and underbilling under AASB 15, fuel tax credits, the Coal LSL levy, payroll tax on contractors, and plant and equipment costing.

Released pack: Australian Accounting Skills v0.2.1. The 10 workflows first shipped as Hardhat Ledger v0.1.5 on 26 August 2026 and now ship only in this pack.

Published 24 August 2026. Last reviewed 27 September 2026.

Each skill encodes the workflow: the steps, the tie-outs and the exceptions to chase. Rates and thresholds go stale and differ by state, so the skill sends the agent to the primary source for them. Two things the skills will not do: decide whether a security of payment Act covers a contract, or conclude that a worker is a contractor rather than an employee. Both stay with a person.

For work in progress, the skills assemble the contract CSV. The arithmetic lives in TheWIPTally, which produces a deterministic AASB 15 schedule. Do not ask the agent to invent cost-to-cost progress, constrained variations or the contract-asset versus contract-liability split.

## What this tool does

- The contracting core: progress claim preparation, retention schedules, work in progress and overbilling and underbilling under AASB 15, and contract cost tracking.
- Mining services and earthmoving: fuel tax credit claims, the Coal LSL levy, payroll tax on contractors, and plant and equipment costing.
- Paying subcontractors: super guarantee under the extended definition, TPAR and a shared reference skill for the exports these workflows need.

## Limits

These skills prepare and check. They do not serve a payment claim, lodge a return or sign anything. Contract interpretation, eligibility conclusions and professional judgement stay with a person. Nothing here is tax, accounting or legal advice.

## Repeat the agent evaluation procedure

Use the evaluation method and its linked validation cards at the same revision. Install that revision, start a fresh session with the target skills loaded and supply the selected card unchanged. Keep the deliberately missing evidence unavailable.

Check the full response against the card’s required checks and prohibitions. Any missed prohibition fails the card. Record the exact model, runtime, source revision, available tools and result; retain the response with the working evidence.

This method measures adherence to visible instructions. It does not test independent error discovery or promise identical wording between runs. Model results require human confirmation before publication; static validation alone does not establish agent behaviour.

## Common questions

### Do I need Claude Code to use these skills?

You need a compatible AI coding agent, such as Claude Code or Codex. These are agent skills, not a standalone program.

### Will they tell me whether a contract is covered by a security of payment Act?

No. Both that conclusion and whether a worker is a contractor or an employee stay with a person. The skills refuse both.

### Do the skills hard-code rates and thresholds?

Not as working figures. Each skill encodes the workflow, the tie-outs and the exceptions to chase, and sends the agent back to the primary source for any rate or threshold, because those go stale and differ by state. Some skills record the figures a person reviewed, with their effective dates, as a cross-check against the live source only.

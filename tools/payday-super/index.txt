# Payday Super: sent on time, received on time?

> See why a synthetic $120 super contribution remains AT_RISK despite timely remittance. Read the fixed facts, engine result, and fund-receipt decision.

# Payday Super receipt evidence

This fixed, synthetic Payday Super example shows why a remittance record cannot establish timely fund receipt. Review aid, not advice; the reviewer decides whether the evidence supports closing the exception.

## Synthetic worked example

Employee SYN001. Payday 6 August 2026. Contribution $120.00, supplied by the preparer. Remitted 14 August 2026. Fund received: no date recorded. Review date 20 August 2026. Ordinary timing pathway. First contribution: no. Out-of-cycle: no.

Result: AT_RISK. The pinned engine calculates a deadline of 17 August 2026. Remittance predates it, but no fund-receipt date proves timely arrival.

Human decision: Obtain evidence of eligible fund receipt and check the applicable timing pathway before closing this exception. Sending does not establish receipt.

This is a fixed example. Nothing to install or upload; these dates do not recalculate. Inspect the exact fixture.

The contribution amount this check tests is set by the super guarantee rate, kept as a maintained table on this site.

Published 24 August 2026. Last reviewed 18 September 2026.

## Try the CSV without cloning

With uv installed, download the synthetic CSV as timely_remittance_no_receipt.csv. Open a terminal in that folder and run:

```
uvx --from payday-super-checker==0.1.4 payday-super-check timely_remittance_no_receipt.csv --as-at 2026-08-20 --confirm-remittance-only -o payday-report.csv
```

The command downloads checker 0.1.4 from PyPI and writes payday-report.csv, replacing that file if it exists. Open it to find one AT_RISK contribution with due date 2026-08-17.

Check the matching evidence before relying on the exported file. In checker 0.1.4, if employee identifiers or pay-period columns are missing, the structural matching warnings are printed to the console but are not carried into the CSV, and which super payment matches which payday can change. Keep the console output with the report, or reconcile affected matches before using a verdict; a row labelled ON_TIME is not reliable evidence of the match itself. See Known limitations (PSC-2).

Exit 0 records your remittance-only acknowledgement. It does not establish timely receipt. Omit --confirm-remittance-only to get the same verdict with exit 2 and a request to resolve or acknowledge the evidence gap.

The fixed example above and the recorded public evaluation use release 0.1.3. Follow that evaluation's revision and commands to reproduce the historical run. This quick trial uses release 0.1.4 and leaves the fund-receipt decision with the reviewer.

## Evidence-pack workflow

The CLI change combines the existing checker and practitioner checklist in one command. It writes report.csv, practitioner-review.md, exceptions.json and a blank decision-log.md into a new directory.

Keep the console transcript with the pack: the CSV report does not carry the structural matching warnings described under Known limitations (PSC-2), so a reviewer who receives only the files cannot see them. Reconcile affected matches before relying on any verdict.

The report omits employee identifiers and input paths. The checklist and exception queue bind to its SHA-256. Every result other than ON_TIME enters the queue; the fabricated example above remains AT_RISK and exits 2. A remittance-only acknowledgement does not clear that queue.

A reviewer uses source row references to reconcile the private input, obtains missing receipt evidence, and records decisions under applicable APES 110 and TPB obligations. Existing decision logs are preserved by refusing an output directory that already exists. The files remain private workpapers containing dates, amounts and warnings.

The companion MCP tool, build_payday_super_evidence_pack, accepts structured contribution rows and returns the 4 files in memory. It accepts no input or output paths, writes no files and records no decisions. It requires a checker with evidence-pack support.

The identifier-free report is for the included checklist. Existing review-pack and PaydaySuper.Report Excel imports require the ordinary checker's 18-column report.

This workflow is included in published checker 0.1.4 and MCP 0.2.2. Checker 0.1.3, used by the historical evaluation, does not include it. Reproduce the recorded development snapshot with fabricated data. No advice, lodgement or ledger write is performed.

## Check the evidence

Reproduced from Payday Super Checker 0.1.3. The release's legal review date is 15 August 2026.

The ordinary timing pathway tests fund receipt within 7 business days of payday. Check whether a different timing pathway applies before relying on the result. Primary sources are the Superannuation Guarantee (Administration) Act 1992 and Australian Taxation Office, LCR 2026/2, as recorded in the evaluation pack.

Source on GitHub · Open an issue

Two known limitations are recorded against this tool: an extrapolated general interest charge rate past the end of the published table, and the ways the payroll-to-super join degrades when identifiers do not match. See Known limitations.

Version, file fingerprints, and timing boundary

Without a fund receipt date, records cannot prove ON_TIME. Remittance timing can still prove LATE, while timely remittance without fund receipt evidence remains AT_RISK.
